## What you need to do now

No coding, installation or Terminal commands are required for the online app. You do not need to supply real company data to finish this portfolio version.

| Your task | Time | What to do |
| --- | --- | --- |
| Try the app once | 5–10 minutes | Choose Try sample data, keep Deals and the suggested mappings, use September 22, 2026 as the analysis date, and click Check data. |
| Explore one change | 2 minutes | Change the stalled threshold from 30 to 60 days. Watch the results change, then restore 30. |
| Keep your outputs | 2 minutes | Download the action plan and run the calculation check. Download its report. |

The personal walkthrough and your comfort explaining the work are the remaining human steps. The saved technical checks are evidence of testing, not a substitute for your own familiarity. If a label or result is confusing, describe what you selected and what you expected in this project task; you do not need to diagnose the code yourself.

## What is included in version 1.0

- CSV/Excel upload, worksheet selection, original-file preview and editable column mapping.
- Full-file validation, specific row-level issues, safe downloads and preservation of all deal rows.
- Open pipeline value, Won value, win rate, counts, average values, Open-deal aging and inactivity.
- An adjustable stalled threshold, four risk categories, exposed value and percentage.
- Charts, filters, stage bottlenecks and optional owner/delay/follow-up summaries.
- Evidence-backed suggestions and a prioritized stalled-deal table.
- Standardized data, issue report, filtered analysis, stage summary, action plan and calculation-check downloads.
- Independent DuckDB SQL age/risk, KPI and stage calculations with visible comparison results.
- Automated calculation and app-interaction tests, saved business definitions and a deployed app.
- Beginner instructions, a demo script, a portfolio case study, interview notes, screenshots and a release record.

## What is not unfinished version-1 work

These are optional future projects, each requiring a separate input/scope decision:

| Extension | What would be needed |
| --- | --- |
| Time to close and monthly outcomes | A mapped, validated close-date field and clear rules for reopened/missing-close records |
| Time in stage or historical funnel conversion | Stage-entry dates or dated stage-change events, not just the current stage |
| Saved analyses and shared company workspaces | Requirements for retention, accounts, access and storage |
| Predictive win/loss probabilities | Suitable historical outcomes, enough representative records, evaluation and a defined business use |
| Currency conversion | A currency field, rate source and conversion-date policy |

None of these is necessary to demonstrate the completed snapshot-analysis portfolio app. Current revenue-at-risk figures are rule-based exposure, not predicted loss or recovered revenue.

## Keeping it working

Bookmark the live link. The app does not maintain a saved analysis history, so download reports you want to keep. The source spreadsheet remains your original record. GitHub contains code and synthetic examples; uploads are not added to that repository by the application.

Request future changes in this project task. Local file edits need publishing to GitHub before they affect Streamlit. The app requires no paid API key for its current features. If the hosted app needs waking, use its on-screen wake/start control. If you see an error, share the wording, selected example or file type, date, threshold and filters; do not send private company records unless they are appropriate to share.
